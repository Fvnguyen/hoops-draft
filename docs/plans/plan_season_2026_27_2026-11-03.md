## Goal

The card pool moves to the 2026-27 season. Players who sat out most of 2025-26 (Trae Young,
Jayson Tatum, Tyrese Haliburton are not in today's 448 cards) come back on their last
healthy season. Rookies appear once they have a few games. Every player is on his 2026-27
team, so the 82:0 opponents match the real league. The card back always shows correct
2026-27 averages, refreshed daily. Ratings come from a games-weighted blend refreshed
weekly, so six games cannot swing a card. In-progress drafts, 82:0 runs and Playoffs
matches keep the card set they started on.

## Decisions (locked)

- **D1 Seasons.** `data/season_config.json`: `{"current": "2026-27", "priors": ["2025-26",
  "2024-25"], "awards": "2025-26"}`. Every script reads it; no season string stays
  hardcoded. Scrapes go to `data/bref/<season>/` (today's snapshots move to `2025-26/` with
  `git mv`). `fetch_bio.py` pulls 2026-27 rosters, so a player's team is his 2026-27 team.
- **D2 Ingest keeps everything.** `fetch_players.py` writes one `SeasonStat` row per player
  per season with GP >= 1 and drops its GP >= 20 filter. Eligibility moves to `ratings.ts`
  (D3), where it is tested. `Player` holds only players on a 2026-27 roster.
- **D3 Eligibility** (`computeCards`). A player gets a card when all three hold: he is on a
  2026-27 roster; he played at least one game in 2025-26 or 2026-27 (nobody returns from two
  seasons out); and either (a) he has a prior: the most recent season in `priors` with
  GP >= 20 and MPG >= 5, or (b) 2026-27 GP >= 5 and MPG >= 15. So a veteran who played in
  2025-26 is in with 0 games this season, and a player with 0 games in both is out.
- **D4 Blend.** `w = gp_current / (gp_current + 20)`, `RATING_CONFIG.season.seasonBlendK = 20`.
  Every numeric `SeasonStat` column becomes `w * current + (1 - w) * prior`; no 2026-27
  games means `w = 0`. The blended row is `card.stats`, so `ratings.ts` and
  `engine/rotation.ts` (reads `stats.mpg`) need no other change. "A starter is never Common"
  uses the blended `gs / gp`. Examples: 6 GP = 23% current, 20 GP = 50%, 60 GP = 75%.
- **D5 Rookies and no-prior players.** Their prior is the rotation-average row: the mean of
  each column over prior rows with MPG >= `RATING_CONFIG.rotationMpg`. Same `w`. Rarity is
  capped at Rare while 2026-27 GP < 20. The under-10-MPG cap (85) still applies.
- **D6 Card stats are current-season actuals, daily.** Display stats live apart from the
  card set in `frontend/public/data/season-stats.json` (`{ asOf, season, players: { [id]:
  SeasonStat } }`), written by `data/refresh_stats.js` from the 2026-27 per-game page only.
  `lib/seasonStats.ts` fetches it once per session (cached by the service worker,
  `?v=<asOf>`); the card back reads it by player id, falling back to
  `PlayerCard.seasonStats` baked into `cards.json` at the weekly build. Label "2026-27 ·
  as of <date>"; 0 GP reads "No 2026-27 games yet". Pinned and old cards show the same
  current stats (cosmetic). `card.stats` (blended) is never shown; `/data` (dev only) shows
  actual, prior, blended and `w`. The OVR/ratings product rule is unchanged.
- **D7 Awards** follow the prior season a card's blend uses (Tatum's come from 2024-25); a
  no-prior player has none. 2026-27 awards count once 2026-27 is a prior.
- **D8 Versions.** `CARD_SET_VERSION` becomes `2026-27.1`, then one step per weekly refresh.
  Before each refresh the shipping set is frozen to `frontend/src/data/cardsets/<version>.json`;
  the repo keeps the four most recent frozen sets (about a month) and deletes older ones in
  the same commit. `engine/cardSets.ts` (pure) exports `loadCardSet(version):
  Promise<PlayerCardData[]>`: current set from `cards.json`, otherwise a dynamic import of
  the frozen file, so the root bundle does not grow.
- **D9 Pinning.** A draft resume (`DraftSession.cardSetVersion`), an 82:0 run (new
  `ChallengeRun.cardSetVersion`, stamped at creation: NBA teams and trade pack) and a Playoffs match (new
  `matches.card_set_version`, null = `2025-26.2`) load their set through `loadCardSet`.
  Tournament seasons need nothing (seats store card snapshots). A version no longer kept
  shows "Started on an older card set" with Abandon only.
- **D10 Headshots.** `ensure-headshots.mjs` never deletes a headshot of a player in any kept
  set. A new player's headshot arrives with the weekly refresh (daily stats need none).
- **D11 Schedule.** `.github/workflows/season-refresh.yml`. Daily 10:00 UTC (after the
  night's games): `npm run refresh:stats`, commit `chore: season stats <date>` to `main`
  only if the file changed. Weekly Monday 11:00 UTC: `npm run refresh:season` (freeze,
  bump, scrape, bio, `fetch_players`, images, `build:cards`) opens a PR `chore: card set
  2026-27.N` whose body carries added/dropped players and rarity counts vs the previous set;
  the owner merges it. If basketball-reference or the NBA Stats API blocks the GitHub
  runner, the same two commands run from a Windows scheduled task on the owner's machine.
  `vercel.json`'s `ignoreCommand` already builds only on `frontend/` changes, so the daily
  commit costs one deployment per day (HANDOVER open issue 8: set Deployment Retention).
- **D12 Balance is report-only** (AGENTS balance workflow, stages 1-4). Pool, OVR, rarity
  and badge distributions are measured against `2025-26.2` for `2026-27.1`; no cutoffs,
  thresholds or `LINEUP_CENTRE` change. Retuning, if needed, gets its own plan.
- **D13 The Supabase migration** follows the production-ops workflow: a rolled-back dry run
  first, then the owner approves applying it to production.

## Out of scope

Aging curves, injury modelling, projections. Retuning rarity or badges for the new pool.
Showing prior-season stats on cards. Merging the weekly PR without the owner.
